# 数据保护与安全发布

用途：参考与发布操作；读者：部署者和贡献者；维护者：项目维护者。

## 资料去哪了

群消息、索引、记忆、人格、运行目标、用量和会话保存在本机持久数据卷。被选入上下文的消息片段、引用、记忆和图片会交给你配置的模型/视觉服务；启用搜索或绘图时还会访问相应服务。本地存储并不代表推理完全离线。

群、用户、公开空间的资料域分别校验。公开空间 Agent 不可直接取群私记忆；转发内容不能作为已认证身份/指令。主人身份只由实际消息发送者与本地 `OWNER_QQ` 判定。

## 永远不要公开的文件

- `.env`、`infra/wsl/.env` 及其备份、代理订阅与服务密码。
- `configs/*.local.yaml`，其中包含真实群、好友和账号许可。
- `configs/personas/`、`data/personas/` 的成员档案、事实与表达样本。
- 全部 `data/`：聊天、数据库/WAL、图片、日志、会话、用量、模型和评估原文。
- `infra/wsl/runtime/`、Docker 数据卷、登录二维码/凭据、QQ 客户端状态。
- 本地任务库、内部项目文档、AI 配置、历史 ZIP、备份 bundle 与发布工具临时目录。

公开仓库保留 `.env.example` 和使用合成账号的模板/测试。**不要整体打包一份已运行过的项目或虚拟磁盘发给别人。** 上传代码时按源码白名单选文件，并核对暂存内容。

## 发布检查

先检查路径，再检查内容，最后检查真正将提交的 blob：

```powershell
git status --short
python -B -X utf8 scripts/check_github_sensitive.py --include-untracked
# 逐项添加已审查的源码/模板/文档/测试，再检查暂存文件。
git diff --cached --name-status
python -B -X utf8 scripts/check_github_sensitive.py
```

门禁拒绝私有路径、API key/GitHub token/私钥模式和本地禁止值。将当前真实账号、群号和密钥登记到 `data/project-tools/.secrets-blocklist`，一行一个值，文件本身也不能上传。检查输出只显示路径与规则，不打印被匹配内容。

忽略规则不能保护已经跟踪的文件，工作树已脱敏也不能清除旧的暂存 blob。扫描通过后仍要核对文件清单及示例值；扫描不会自动证明所有历史提交安全。

发现已公开凭据时先撤销/轮换，再审查 Git 历史修复方案。普通更新采用正常提交，不能把覆盖代码理解为允许删除提交历史或强制推送。

## 服务与操作边界

本栈使用 host 网络。管理端口、OneBot、noVNC/VNC 与计算端点应只向可信本机开放或受防火墙保护。SnowLuma 及 QQ 客户端需要自己的发行许可；使用者负责账号授权和平台规则。

示例部署中的 OneBot 无令牌适配只能在本机受保护网络使用。WebUI/VNC 设置独立强密码。计算 Token 仅交给可信应用与 gateway，不放入模型提示词。

计算 gateway 持 Docker socket，相当于高权限服务；模型代码在独立受限容器运行，不能把 gateway 的权限当成模型自己的权限。不得将 gateway 暴露到公网，禁用时不允许回退宿主执行。

主人指令只开放已启用行为，不提供宿主 Shell 或项目文件控制。授权可持续生效，发布空间或评论不会每次都先人工审批；开关、好友范围、静默时间和预算应由部署者先确认。

未知外部回执记为 uncertain，不自动重试，以避免重复消息或重复评论。明确拒绝、请求超时、应用就绪和实际平台成功是不同结果。

## 备份与清理

生产 SQLite 使用 backup API 创建一致副本并验证 `integrity_check`，不要直接只复制正在写入的 `.db` 而忽略 WAL。登录卷和业务卷分别备份。备份与评估原文都按私有资料保存。

可清理旧发布、闲置镜像/构建缓存和已结束测试夹具，不能删除现役卷、当前 release、当前镜像、计算执行基础镜像或正在使用的模型。Docker image prune 不理解业务是否未来需要某个作业基础镜像，须先核对消费方。

清理 Linux 文件不会自动让 Windows 上的 WSL VHD 同步缩小；需要另行在停止服务、退出 WSL 后进行受控压缩，并恢复检查。具体方法见 [运维指南](../infra/wsl/README.md)。
